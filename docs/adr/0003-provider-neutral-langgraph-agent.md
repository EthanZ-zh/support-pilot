# ADR 0003：Provider 中立的 LangGraph 受控工作流

- 状态：Accepted
- 日期：2026-08-30

## 背景

SupportPilot 需要把意图识别、RAG、业务工具、风险门控和人工升级连接成可解释的状态机。直接使用无限 ReAct 循环会使调用次数、副作用和失败路径难以约束，也会把业务规则交给模型。

## 决策

采用 LangGraph `StateGraph` 构建显式分支工作流；模型只通过 `DecisionProvider` 产生结构化决策。租户授权、风险分级、工具参数完整性、Answerability、工单确认和审计仍由确定性代码控制。

首个增量使用无循环 DAG，并设置执行上限。每次运行把结果快照和逐节点 Trace 保存到 PostgreSQL。当前持久化用于诊断与审计；可恢复 checkpoint 在多轮人工介入实现时再引入，避免当前同时维护两套不必要的状态存储。

## 替代方案

- 手写 if/else：依赖最少，但随着人工中断、多轮和恢复增加，会失去显式图和状态迁移能力。
- 预置 ReAct Agent：原型快，但工具循环、提示词和停止条件不够贴合本项目的风险边界。
- 微服务式工作流引擎：当前规模没有部署和运维收益。

## 代价与验证

增加 LangGraph 依赖和状态 Schema 维护成本。通过路径级集成测试、有限重试测试、无副作用断言、数据库 Trace 和后续 Agent 场景评测验证。
