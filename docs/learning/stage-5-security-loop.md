# 第五阶段学习说明：认证、RBAC 与人工接管

## 30 秒讲法

“SupportPilot 用短期 JWT 完成身份认证，数据库角色和租户做最终授权。客户只能读自己的工单，支持人员领取后按有限状态机推进。所有人工写操作同时用幂等键和版本号防止重复与并发覆盖，并记录不可变审计；人工反馈只进入候选数据，不直接污染知识库。”

## 3 分钟请求链路

1. 登录端点用 Argon2id 校验哈希，签发带 `sub/tid/role/iss/aud/exp/jti` 的 HS256 Token。
2. API 只接受 Bearer；解码后再次读取当前用户，角色、租户或状态漂移立即拒绝旧 Token。
3. 客户查询工单时 SQL 固定加入 tenant 条件；内部角色才可跨租户查看。
4. `claim` 锁定 Ticket 行，检查 support role、幂等记录和 `expected_version`，再原子执行 `open → triaged + assignee`。
5. `transition` 还要求 actor 是 assignee，并调用确定性状态机；非法路径绝不交给 LLM 判断。
6. Feedback 必须关联同会话 Ticket 与 AgentRun，评论先脱敏，并通过唯一约束和幂等记录去重。
7. 所有拒绝与成功写入 AuditEvent，因此能解释谁、何时、对什么资源、因何被允许或拒绝。

## 高频追问

- 为什么 JWT 验证后还要查数据库？——为了让禁用、角色或租户变化立即生效，避免旧 Claim 长时间保留权限。
- 幂等键和 version 有什么区别？——幂等键解决同一意图重复提交；version 防止两个不同意图基于同一旧状态互相覆盖。
- 为什么不用 LLM 判断状态转换？——状态机是业务不变量，需要确定性、可测试和可审计。
- HS256 有什么限制？——签发和验证共享密钥，适合单体；跨服务/企业 IdP 更适合 OIDC + 非对称 JWKS。
